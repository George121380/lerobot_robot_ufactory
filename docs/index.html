GELLO / xArm

Joint-space teleoperation, demonstration recording, and LeRobot policy rollout.

Python 3.12 · LeRobot 0.6.1 · Source: 5fe6fb1
Draft 0.3 — not yet tested on lab hardware.

Required: xArm + gripper, powered GELLO leader, cameras, and an Ubuntu workstation with network/USB access.

Install

git clone https://github.com/George121380/lerobot_robot_ufactory.git
cd lerobot_robot_ufactory
conda create -n uf_lerobot python=3.12 -y
conda activate uf_lerobot
python -m pip install -e ".[gello]"
python -m pip check

Find the GELLO serial port:

ls -l /dev/serial/by-id/

If the device requires dialout access, run this once, then log out and back in:

sudo usermod -aG dialout "$USER"

Configure

Examples: xArm5 · xArm6 · xArm7.

export XARM_MODEL=6  # Change to your arm's DOF: 5, 6, or 7
mkdir -p config/local
cp "config/gello/xarm${XARM_MODEL}_gello_record_config.yaml" config/local/lab_gello.yaml
export LAB_CONFIG="$PWD/config/local/lab_gello.yaml"

Edit $LAB_CONFIG. config/local/ is ignored by Git.

FieldSet to
robot.robot_ip, robot_dof, gripper_typeActual controller, arm DOF, and gripper.
robot.control_spacejoint for collection and rollout.
robot.start_joints, teleop.start_jointsMatching reference postures, in degrees; one value per joint.
teleop.portThe GELLO serial path above.
teleop.joint_ids, joint_signsLeader motor IDs and directions, in follower-joint order.
teleop.gripper_id, torque_joint_idsActual motor IDs. Torque is enabled on torque_joint_ids at startup.
robot.max_joint_velocityJoint-command speed in degrees/s; startup uses separate motion calls.
dataset.root, repo_idNew absolute folder and namespace/dataset_name.
dataset.single_task, fps, push_to_hubTask description, 30 FPS initially, false for local recording.

Replace all example device IDs and dataset paths. The xArm7 example reuses an xArm6 dataset name.

Cameras

GELLO examples omit cameras. Add this under the existing robot: key; replace the device path and select a supported mode:

  cameras:
    front:
      type: opencv
      index_or_path: "/dev/v4l/by-id/REPLACE_WITH_CAMERA_ID"
      width: 640
      height: 480
      fps: 30

Keep camera names, mounts, and image sizes fixed through collection and rollout. Other camera backends need their own configuration.

Units: joint observations/actions are absolute radians; start_joints is degrees. gripper.pos: 0 open, 1 closed.

Align GELLO

  1. Before launching, put GELLO in the configured reference posture with its gripper input open.
  2. Check joint IDs, signs, and one start_joints value per arm joint.
  3. Test small movements, one joint at a time, then check gripper opening/closing.
  4. Before a new episode, return GELLO to the reference posture. Before resuming, match the follower's current posture.

Offsets are calculated at process startup. Space/reset does not recalibrate GELLO. Source

Connecting or resetting can move the arm and open the gripper, even with no_action: true. Clear the workspace and know the physical stop procedure; Space is only a software pause.

Teleoperate

uf-robot-teleop --config_path "$LAB_CONFIG" --fps 30
KeyAction
SpaceStart / pause.
←Request reset; starting again homes the follower.
EscExit.

This command disables cameras. Check camera feeds separately before recording.

Record

uf-lerobot-record \
  --config_path "$LAB_CONFIG" \
  --dataset.num_episodes=3 \
  --dataset.episode_time_s=30 \
  --dataset.push_to_hub=false
KeyAction
SpaceHome the follower and start an episode.
→Save the episode. The time limit also triggers saving.
←Discard and re-record.
EscExit; save first to keep the current episode.

Reset objects between episodes. reset_time_s is unused.

Resume the same dataset and configuration:

uf-lerobot-record --config_path "$LAB_CONFIG" --resume true

Inspect

Use the root and ID saved by the recorder:

export DATASET_ROOT="/absolute/path/to/recorded_dataset"
export DATASET_ID="your_namespace/your_dataset"

lerobot-dataset-viz \
  --root="$DATASET_ROOT" \
  --repo-id "$DATASET_ID" \
  --episode-index 0 \
  --display-compressed-images true
  • All cameras present, updating, and showing the task.
  • Joint/gripper traces match the video; no unexplained jumps.
  • Episode boundaries and task label correct; recording keeps up with FPS.

Train

ACT pipeline check with camera observations; 2,000 steps is not a task-performance target.

export RUN_DIR="$PWD/outputs/act_$(date +%Y%m%d_%H%M%S)"

lerobot-train \
  --dataset.root="$DATASET_ROOT" \
  --dataset.repo_id="$DATASET_ID" \
  --policy.type=act \
  --policy.device=cuda \
  --policy.push_to_hub=false \
  --output_dir="$RUN_DIR" \
  --job_name=act \
  --steps=2000 \
  --batch_size=8 \
  --save_freq=1000 \
  --wandb.enable=false

Check input features, finite loss, and saved checkpoints. Split training/validation data by episode.

Run a policy

Use the same joint/gripper schema, cameras, and FPS as collection. Keep control_space: joint and the default relative=False.

export POLICY_PATH="$RUN_DIR/checkpoints/last/pretrained_model"

uf-lerobot-eval \
  --config_path "$LAB_CONFIG" \
  --dataset.root="$DATASET_ROOT" \
  --dataset.repo_id="$DATASET_ID" \
  --policy.path "$POLICY_PATH"
KeyAction
SpaceStart / pause / resume.
←Stop the trial; starting again resets the robot and policy.
EscExit.

GELLO cannot take over in this loop. n_episodes does not stop execution; end trials manually and log success/failure.

Troubleshooting

ProblemCheck
Serial access / read failureGELLO power, serial path, dialout membership, motor IDs, and another process using the port. Baud rate: 57600.
Wrong joint / directionjoint_ids, joint_signs, arm DOF, and reference arrays.
Jump on start / resumeLeader posture at startup and before resuming. Offsets persist until the process restarts.
Gripper inverted / saturatedStart with the input open. The adapter uses fixed endpoints at the startup angle minus 0.2° and 42°.
No imagesAdd robot.cameras; GELLO examples have none. Check device paths, camera backend, and supported modes.
Slow recordingCamera resolution/FPS, USB bandwidth, encoding load, and disk speed.
Dataset existsUse --resume true for the same collection, or choose a new root/ID.
Policy feature mismatchJoint count, gripper, optional velocity fields, camera names/shapes, and checkpoint preprocessing.

gripper_id: -1 needs a code fix: the adapter still reads a gripper action. Rollout smoothing does not apply to joint targets.
